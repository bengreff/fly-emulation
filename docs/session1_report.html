Fly emulation · Session 1 · 14 September 2026

Every route to real firing rates costs the rhythm

An overnight grounding pass on the connectome-constrained fly nerve cord. The published result reproduces cleanly. Then four independent attempts to push its motor output into the range a real muscle needs each destroyed the very rhythm the model was built to show.

What this was

You asked for grounding. So rather than build infrastructure, I took the strongest existing connectome-constrained simulation of the fly's motor system, reproduced it independently, and then attacked it with the controls the project's own documents demand. The aim was one honest measured result and a clear view of what actually blocks walking.

The subject is the ventral nerve cord, the fly's equivalent of a spinal cord, which drives the legs. A recent study built a 4,604-neuron model of its front-leg circuitry directly from the wiring diagram, stimulated a single descending command neuron, and reported rhythmic motor output resembling a stepping pattern generator. That is the strongest published precedent for this project and the right thing to stand on.

Terms used below

Connectome
A complete electron-microscope wiring diagram: every neuron and every synapse between them, in one individual animal.
Ventral nerve cord
The fly's spinal-cord equivalent. Contains the circuits that drive the legs and wings.
Descending neuron
A neuron carrying commands from the brain down into the nerve cord. DNg100 and DNa02 are two named ones.
Motor neuron
The final output cell. Its spikes contract one muscle. The front leg has 144 of them.
Proprioceptor
A sensor reporting the limb's own position, movement or load back to the nervous system.
Rhythmicity
A 0–1 score for how periodic a cell's activity is. 0.8 is a clean oscillation; 0.1 is noise.

The headline

The model has two knobs that matter and a couple of other ways in. Every one of them trades the same two things against each other: how rhythmic the motor output is, and how hard the motor neurons actually fire. The published parameter setting sits at one extreme, with a beautiful rhythm and almost no motor output.

This is not a defect I found in someone's code. It is a property of the model class: a nerve cord cut off from its body, driven by a constant injected current, with a single global number converting synapse counts into synaptic strength. Knowing exactly where that class breaks is the useful thing.

The evidence, in order

F1

A units bug in the published analysis code

The oscillation-frequency function in the reference repository builds its time axis from sample indices, so what it returns is cycles per sample, not hertz. At the default 1 ms timestep the number must be multiplied by 1000. I caught it because a visibly ten-times-per-second rhythm was being reported as 0.01 Hz.

Three estimators on the same traces, 0.5–1.9 s
EstimatorFrequency
Library value × sampling rate9.47 Hz
Periodogram peak11.43 Hz
Threshold crossings10.7–11.4 Hz

An independent periodogram estimate now runs alongside every frequency the pipeline reports, and a unit test pins a synthetic 20 Hz signal. The residual 5–15% spread between estimators is genuine estimator disagreement on a short window, and is carried as uncertainty rather than hidden.

F2

The anatomy joins cleanly, and an outside measurement agrees

Every one of the 144 motor neurons in the simulated network matched a nerve-cord annotation on exact integer identifier, with a named target muscle and traced status. No silent losses, no fuzzy name matching.

The useful part is the corroboration. The tibia flexor pool, the muscle group that bends the lower leg, contains exactly 15 motor neurons per side in the wiring diagram. An electrophysiology study that never touched this connectome reports that tibia flexion is controlled by "approximately 15 motor neurons." Two entirely independent methods agree on the size of the pool, and cell body size across that pool spans 13-fold, matching the size gradient the same study describes.

That is the anatomical bridge Milestone A needs, and it holds.

F3

The rhythm reproduces. The amplitude does not.

Sixteen independent draws of the unmeasured biophysical parameters, solver tolerances as published. A strong rhythm near 10 Hz appeared in every single one.

The model's peak is roughly thirteen times below the resting rate of the one leg motor neuron whose rate has actually been measured. The units that produce usable force, which generate about one fly body weight per spike, never come near threshold. Only three motor neurons fire at all, all of them serving hip muscles on one side. The entire lower leg stays silent.

What this is not. It is not evidence the model is wrong. It is evidence about what the model is: a preparation with its sensory nerves cut. Which leads directly to the next finding.
F4

The specific wiring is doing real work

The control the project documents demand: compare the real connectome against a carefully matched alternative, not a crippled one. The shuffle preserves every neuron's outgoing connection count and weights exactly, and preserves the excitatory–inhibitory composition of each cell class. Only which cell receives each connection changes.

Shuffling makes the network simultaneously hyperactive and arrhythmic: about twenty times more neurons active, and the rhythm largely gone. The pattern of connections, not merely how many each cell has, is what holds this circuit in a sparse oscillating regime. This is the strongest evidence from the session that the anatomy carries real functional information.

Caveat I would fix before quoting this. The shuffle preserves outgoing degree exactly but reassigns incoming patterns across cells of a class, so it is not a perfect degree-preserving null. A stricter null should be run.
F5

The full sensory apparatus is in the model, and none of it is switched on

The network contains 285 sensory neurons. Every class that reports leg state is present.

102 of these are proprioceptors, the afferents whose firing during stepping is the main sensory drive to insect leg circuits. In the published protocol all of them sit at exactly zero.

A data gap found by trying to fix it. The definitive study of the fly's main leg proprioceptor characterises it with calcium imaging. It reports which subgroup encodes position, direction and vibration, and over what joint-angle range. It reports no firing rates. There is no published rate calibration with which to drive these neurons. Any sensory amplitude used here is a swept unknown, recorded as such in every run record, never as a measurement.
F6

The best available fly body can receive two thirds of the motor output

The body-platform question the roadmap left open is largely closed: one package now ships the walking body, the flight body, a musculoskeletal model and GPU physics. But the muscle model exposes 15 actuators on the left front leg only, with the other leg's joints locked. Mapping the connectome's motor neurons onto it:

Absent entirely: the femur reductor, all tarsus muscles, meaning no active foot, and the long tendon muscles. Worse for our purposes, the 15-neuron tibia flexor pool, the one group with excellent published physiology, collapses onto a single actuator. The size principle that the fly actually uses to grade force cannot be expressed at all.

So closing the leg loop is not a wiring-up exercise. A third of the motor output has nowhere to go, and the best-measured muscle in the animal cannot resolve its own motor units. Extending the muscle model is prerequisite work.

Add the fifth route, switching the silent proprioceptors on: median peak motor-neuron rate rises from 2.3 Hz to 82.6 Hz, comfortably physiological, and active motor neurons from 3 to 67 — while rhythmicity falls from 0.836 to 0.281 and the frequency drops to 4 Hz.

One more thing worth noticing in that table. With no stimulus the network is exactly silent, all 4,604 cells at zero. Real nervous systems are never silent. Whatever supplies that baseline in the animal is simply absent here, and it is plausibly part of what sets resting motor-neuron rates in the first place.

What I think is going on

Three candidate explanations, in the order I would spend effort on them.

  1. Sensory feedback is not tonic, and I tested it as if it were. Real proprioceptors are modulated by the leg's own movement; that is the entire point of them. Driving all 102 with a constant current is the worst possible caricature of that input. The controlled version — same mean drive, rhythmically modulated instead of constant — is running now.
  2. One global synaptic scale is too crude. Setting strength proportional to synapse count times a single multiplier is the field's standard starting assumption, not a measurement. Cell-type-specific gains fitted against physiology are the next move if the first explanation fails.
  3. There is no background activity. See the exact zeros above.
Every result above rests on scaffolds, and they are recorded. A current is injected directly into a command neuron, which reproduces an optogenetics experiment and is not spontaneous behaviour. Synaptic weight is synapse count times a global constant with sign guessed from a transmitter prediction, which is not measured efficacy. Sensory drive, where used, is imposed rather than generated by a body. Each run's provenance file lists these explicitly so no later reader has to reconstruct them.

What was built

Small and executable, per the project's own instruction to avoid platform-building. Every run writes a provenance record: code commits for this repo and the pinned upstream, SHA-256 of every input file, resolved configuration, environment, wall time, peak memory, and the explicit list of scaffolds.

uv run pytest tests -q                      # 7 checks pass
./scripts/run_condition_set.sh 16           # the five conditions
uv run python scripts/pugliese_conditions.py --condition baseline \
    --replicates 8 --sensory-amp 200        # switch the proprioceptors on
uv run python scripts/phasic_sensory.py --sensory-amp 200 --freq 10
uv run python scripts/make_figures.py

The tests pin the things that quietly ruin this kind of work: frequency units, the anatomical identity join being total and exact, the tibia flexor pool matching the independent count, the weight matrix being signed and integer-valued, and solver determinism under a fixed seed.

Both machines were used. The Windows box's internet is blocked at your router, so its Python environment was built from wheels downloaded on the laptop and shipped over the Tailscale link. Worth recording: the same simulation on Apple silicon with one JAX version and on x86 with a different one returned identical readouts to three decimal places. Architecture and library version are not a source of drift here.

The next experiment

Running now: phasic versus tonic proprioceptive drive at matched mean amplitude. If the rhythm survives rhythmic sensory input but dies under constant input of the same average strength, then the timing of sensory feedback is what matters, and an embodied loop is required rather than merely desirable. That would be the cleanest possible argument for the direction this project is already pointed.

After that, Milestone A in dependency order: resolve the tibia flexor into its 15 motor units anchored to the measured per-spike forces; add the missing muscles; build afferent transducers with the rate scale declared as fitted; then close the loop and ask the question this session could only pose. One published perturbation stays untouched by any fitting step, as the first real test of causal organisation.

What would make me change route. If body-generated feedback still cannot produce both physiological rates and a stable rhythm, the synapse-count weight assumption is the prime suspect, and the work moves from body engineering to fitting per-cell-type synaptic gains against physiology.
