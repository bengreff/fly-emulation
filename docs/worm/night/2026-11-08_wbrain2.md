  ("Delete: gbkcnl"). `cainternn.mod` (Metaworm `modfile_d`, the only set that has it) is algebraic:
  cai = gbcav (60 - v) 1e12/(8 pi r D F) exp(-r/lambda), the Nicoletti 2019 nanodomain with the summed SLO density
  (nS/um2) in place of the single-channel conductance (nS). In `modfile_d` the four SLO mods READ that cai; in the
  network's set (`eworm/components/mechanism/modfile`, our vendored mods) each SLO computes its own nanodomain from
  gsc = 40 pS. So cainternn vs cainternm is not a bulk-pool question: in the tuner no mechanism reads a bulk pool
  (KCNL absent, Ca channels use E_Ca = 60 mV fixed), and the SLO channels saw sum(gbslo)/0.04 of the network's
  nanodomain Ca: 0.104x to 1.5x over the 220 cells with SLO, median 0.147x (derived from the cell JSONs). Inferred, not
  certain: the tuner's own mechanism directory (`single_nrn_tune/data/mechanism`) is not in the clone, but
  `modfile_d` is the only set where `gbcav` reaches anything.
