## Step 0: the two failing tests

`tests/test_worm_ca_volume.py` (fixed_form_neutral, whole_cell_and_soma_forms) died with `ValueError: lam value too
large` in `mech/noise.py` `Shot.step`. Bisected on the test's 4-cell brain (AVAL, AIYL, AWCL, dBWML6; 20 pA into
every cell from step 100 to 200): of the 42 code Specs whose ledger value now differs from the code template, one
alone trips it, `rec_glucl_hill` 1.0 -> 1.5 (the catalog's literature value). Mechanism:

- AIYL in this 4-cell brain is near-passive with a very high input resistance: 20 pA takes it to +108 mV at hill
  1.0 (measured) and to +168 mV at hill 1.5. Voltages above every reversal potential are the saturation problem
  (not chased; Open).
- BAAIWorm's graded release sets tau = (1 - sinf)/k. Once vpre is above Vth + about 37 delta (-20 + 37 x 5 = +165
  mV), sinf rounds to exactly 1.0 in double precision and tau = 0. NEURON's cnexp update then computes
  (sinf/tau)/(1/tau) = inf/inf = NaN in the release state s; gap junctions spread the NaN to every cell in one
  step; noise's Poisson draw is the first thing to raise on it.
- So the catalog value is fine; the mod's numerics were fragile. Fix in `src/wormemu/nmodl/wsyn.mod` `rates()`:
  where tau <= 0, recompute it as 1/(k (1 + exp((vpre - Vth)/delta))), the same quantity without the cancellation
  (exponent capped at 700). Identical wherever tau > 0, so every exact-equivalence test is untouched. The Python
  reference (`mech/plasticity.py` line 162) already had a tau = 0 branch.
- After the fix the 4-cell case runs to the end (V at step 300: -67.1, -31.0, -44.9, -50.0 mV).
